# Этап 1. Собрать сайт-визитку локально

Это инструкция для Claude Code. Прочитай её целиком, дальше работай по ней.

Пользователь — руководитель, не программист: не знает, что такое DNS, FTP и сертификат, и **не должен разбираться**. Объясняй простыми словами, всю техническую работу делай сам, спрашивай только про содержание, про то, что нравится визуально, и про действия, которые физически может сделать только сам пользователь: оплата картой, вход в личные кабинеты, нажатие кнопок в панелях.

Работа разбита на два этапа. Этот файл — первый: собрать сайт на компьютере пользователя и довести до состояния «нравится». Публикация, домен и хостинг — второй этап, отдельный файл `02-publish.md`. **Не начинай второй этап, пока пользователь явно не скажет**, и не забегай вперёд по домену и хостингу.

## Шаг 0. Окружение

Первым делом спроси, какая система на компьютере: **Windows или macOS**. Дальше веди строго по своей ветке и не давай команд из чужой. Если система не из этих двух (например, Linux) — своей ветки под неё в этом файле нет; ближайшая — macOS, с тремя поправками: git ставится пакетным менеджером дистрибутива, страница открывается командой `xdg-open`, а `curl` и `dig` пишутся так же, как в ветке macOS; `dig` при этом на Linux часто идёт отдельным пакетом и может отсутствовать — понадобится он только на этапе 2.

### 0.1. Ветка Windows

**Сначала git — он меняет твой собственный шелл.**

На Windows Claude Code выполняет команды через PowerShell, а при установленном Git for Windows — через Bash. То есть установка git меняет инструмент, которым ты работаешь, прямо посреди сессии. Поэтому это первое действие, а не попутное.

1. Проверь: `git --version`.
2. Нет git — проведи через установку: `winget install --id Git.Git -e`, либо загрузка установщика с `git-scm.com/downloads/win` и обычное «Далее-Далее». Кнопки нажимает пользователь.
3. **После установки нужно перезапустить не терминал, а сам Claude Code** — иначе шелл не переключится. Предупреди заранее и дождись возвращения. Перед закрытием обязательно скажи: новая сессия стартует без памяти о разговоре, поэтому в новом окне надо снова перетащить тот же файл `01-build-site.md`, с которого начинали, и написать «продолжаем с того же места». Иначе пользователь вернётся к пустому окну и не поймёт, что делать.

**Команды пиши так, чтобы работали в обоих шеллах.**

- **`curl` пиши только как `curl.exe`.** В PowerShell голое `curl` — это псевдоним для `Invoke-WebRequest`, а не настоящий curl: команда упадёт с ошибкой про неизвестный параметр, и ты можешь ошибочно решить, что curl не установлен. Он установлен: в Windows 10 и 11 `curl.exe` входит в систему.
- **Для DNS используй `nslookup`**, а не `Resolve-DnsName`: первый работает и в PowerShell, и в Bash, второй — только в PowerShell.
- Открыть собранную страницу в браузере: из Bash — `start index.html`, из PowerShell — `Start-Process index.html`. Проверь, в каком шелле ты находишься, прежде чем звать команду. Команда не сработала — не чини её и не трать на это время: попроси открыть файл `index.html` двойным кликом, по рамкам ниже страница обязана открываться так.

**Кодировка.** После первого коммита выполни `git log -1` и посмотри, читается ли русский текст. Если вместо букв мусор — переключись на английские сообщения коммитов и не трать на это чужое время.

### 0.2. Ветка macOS

1. Проверь: `git --version`. На чистой системе эта команда вызывает окно установки Xcode Command Line Tools. Предупреди заранее, что окно сейчас появится, попроси нажать кнопку установки и дождись окончания — это несколько минут. Отдельно ставить git не нужно, он входит в этот набор.
2. Команды пиши как есть, без суффикса `.exe`: `curl` здесь настоящий curl, для DNS — `dig`.
3. Открыть собранную страницу в браузере: `open index.html`. Команда не сработала — не чини её и не трать на это время: попроси открыть файл `index.html` двойным кликом, по рамкам ниже страница обязана открываться так.

### 0.3. Общее для обеих веток

**Проверь `git config user.name` и `user.email`.** Пусто — коммиты будут падать. Спроси имя и почту, пропиши сам.

**Если git установить не удалось** (корпоративная политика, нет прав администратора — на рабочем ноутбуке это обычное дело): не буксуй. Работай без git, скажи об этом прямо, а вместо отката через историю делай копию папки проекта перед каждой рискованной правкой. Всё остальное в этом файле от git не зависит.

**Проверь путь к папке проекта.** Выведи текущий путь. **Если в нём есть кириллица, пробелы или синхронизируемая с облаком папка** — предложи переехать: на Windows в `C:\site`, на macOS в `~/site`. На Windows путь обычно выглядит как `C:\Users\<имя>\OneDrive\Рабочий стол\...`, на macOS «Рабочий стол» и «Документы» часто лежат внутри iCloud Drive; встречается и Dropbox. Кириллица в пути и папка под синхронизацией регулярно дают блокировки файлов и странные ошибки, которые пользователь не сможет диагностировать. Переезд занимает минуту, а разбирательство потом — час.

Не уводи проект за пределы папки, из которой тебя запустили, без ведома пользователя: выход наружу вызовет запросы разрешений, смысла которых пользователь не поймёт. И учти главное: **свой рабочий корень ты не сменишь сам**, одним `cd` переезд не делается. Порядок такой — попроси создать пустую папку через Проводник (на macOS — Finder), закрыть Claude Code и запустить его заново уже из этой папки, тем же способом, каким запускал в первый раз. Предупреди, что на это время ты пропадёшь, и дождись возвращения. Перед закрытием обязательно скажи: новая сессия стартует без памяти о разговоре, поэтому в новом окне надо снова перетащить тот же файл `01-build-site.md`, с которого начинали, и написать «продолжаем с того же места». Иначе пользователь вернётся к пустому окну и не поймёт, что делать. Если старые файлы уже есть — скажи, что перенести, прежде чем закрывать.

**Объясни, как передавать тебе файлы.** Понадобится дважды: фотография на этом этапе и скриншоты панелей на этапе 2.

- **Файл** — перетащить в окно Claude Code.
- **Скриншот** — на Windows `Win+Shift+S`, выделить область, **сохранить в файл**; на macOS `Cmd+Shift+4`, выделить область — снимок сам ляжет файлом на рабочий стол. Дальше в обоих случаях перетащить файл в окно. Не полагайся на вставку из буфера: поведение неодинаковое, а скриншот — твоя главная страховка против выдуманных пунктов меню на этапе 2. Проговори этот путь один раз в начале, чтобы потом не объяснять в момент, когда что-то уже пошло не так.

## Жёсткие технические рамки

Действуют на обоих этапах. Не отступай от них и не предлагай другой стек, даже если считаешь его лучше.

- Сайт — **три файла**: `index.html`, `styles.css`, `script.js`. Не сваливай всё в один файл: правки должны быть точечными. Вторая страница, если понадобится, — просто ещё один `.html` рядом.
- Никакой сборки: без npm, без Node, без React, без Next.js, без Tailwind, без сборщиков и препроцессоров.
- Никаких внешних загрузок во время работы страницы: шрифты только системные, иконки — inline SVG или текст, картинки — локальные файлы рядом. Google Fonts, любые CDN и внешние скрипты не подключать: из России они грузятся нестабильно.
- Иконка вкладки (`favicon`) — inline SVG в `data:`-ссылке, чтобы браузер не сыпал ошибками. Внешним файлом не подключать.
- Страница должна открываться двойным кликом по файлу и полностью работать без интернета.
- Вёрстка адаптивная, нормально смотрится на телефоне.
- `script.js` нужен ровно для двух вещей: плавная прокрутка по якорям и мобильное меню. Всё остальное рамка запрещает — не изобретай применение файлу.
- Аналитика, чат-виджеты, баннеры про куки — не добавлять.

## Цель этапа

Пользователь открывает сайт в браузере, видит его целиком, без дыр и заглушек по содержанию, и говорит «нравится». Публикация — отдельный этап, сюда не лезь.

## Создай проект

В рабочей папке:

```
index.html
styles.css
script.js
assets/            — сюда положим фотографию
CLAUDE.md          — короткая памятка проекта
01-build-site.md   — копия этого файла (см. «Памятка и копия этого файла»)
.gitignore
```

В `.gitignore` с самого начала внеси `deploy-creds*` — это имя файла с доступами к хостингу, он появится на этапе 2. Заведи строку сейчас, чтобы потом не забыть.

Сделай git-репозиторий и первый коммит. Дальше коммить после каждого «ок», сообщения к коммитам — по-человечески: пользователь должен понимать историю, если однажды в неё заглянет.

## Собери контент

Задавай **по одному вопросу за раз**. Не выдавай список из десяти пунктов.

**Домен.** Спроси, есть ли уже домен и какой именно. Есть — запиши в `CLAUDE.md`, он понадобится на этапе 2. Нет — скажи, что домен покупается на этапе 2, это несколько минут и небольшие деньги, а на этапе 1 он не нужен. **Не блокируйся из-за домена и не отправляй покупать прямо сейчас.**

**Готовый текст.** Возможно, структура сайта и описание экспертизы уже написаны раньше — в чате с ИИ или в обычном документе. Спроси и попроси прислать копипастом. **Если готового текста нет — не блокируйся:** собери его сам коротким интервью, по одному вопросу, и покажи результат на утверждение.

**Портрет.** Попроси перетащить файл в окно и положи в `assets/`. Если фото сейчас нет — поставь аккуратную временную заглушку того же размера и пропорций, что и будущее фото, скажи, что заменишь одной фразой, и спокойно иди дальше.

**Цифры, 3–4 штуки.** Годы опыта, масштаб компаний, число проектов, советы директоров и подобное. Если пользователь затрудняется — задай пять наводящих вопросов, по одному за раз, и помоги сформулировать.

**Результаты, 2–3 штуки** в формате: цифра, в чём была задача, что сделано. Если сходу не вспоминается — задай наводящие вопросы так же, как для цифр: за какой проект не стыдно, что там было на входе, что стало на выходе, есть ли число. **Если материала всё равно нет — не оставляй раздел с заглушками: убери его целиком** и скажи, что вернём, когда будет что показать. Сайт с дырой посередине показывать нельзя.

**Контакты.** Telegram обязателен, почта — если дадут. Не дают почту — раздел собирается с одним Telegram, это нормально, переспрашивать не надо.

---

## Про текст — важное

**Не выдумывай за пользователя факты, цифры и достижения.** Чего нет — спрашивай.

Это относится не только к цифрам. Абзацы «обо мне» и описания в карточках экспертизы — это позиция пользователя, а не твоя. Если ты напишешь их сам «по смыслу», получится гладкий обезличенный текст, который читается как сгенерированный, и для персонального сайта это провал. Правильный ход: попроси объяснить своими словами, как пользователь описывает это клиенту вживую, и **редактируй сказанное, а не сочиняй за него**. Сокращать, резать, переставлять — можно и нужно. Придумывать смысл — нет.

## Структура страницы

Блоки строго в этом порядке:

1. **Шапка** — имя, одна строка позиционирования (кто и для кого), портрет, кнопка «Связаться» со ссылкой на Telegram.
2. **Плитки с цифрами**, 3–4 штуки: крупная цифра, под ней короткая подпись.
3. **Обо мне** — два-три коротких абзаца, не больше.
4. **Экспертиза** — 3–4 карточки. В каждой: заголовок, уточняющий подзаголовок в одну строку, абзац «когда я нужен и что делаю».
5. **Результаты** — 2–3 блока в формате цифра / вызов / решение. Раздел опускается, если материала нет (см. «Собери контент»).
6. **Контакты** — Telegram ссылкой, почта если есть. Форму обратной связи не делать.

Сверху — тонкая панель навигации с якорями на разделы, липкая при прокрутке.

## Дизайн

**Рамка:**

- Ширина контента максимум 1100 px, по центру.
- **Расстояние между соседними секциями — 80–120 px суммарно**, а не 80–120 сверху плюс столько же снизу. Проверь итоговый зазор на собранной странице, а не по значениям в CSS.
- Палитра: три цвета, не больше — фон, текст, один акцентный цвет. По умолчанию фон светлый, текст почти чёрный. Тёмный фон допустим только в тёмном стиле из списка ниже: там та же пара фона и текста работает в двух инверсиях, светлой и тёмной, новых цветов от этого не прибавляется, и акцент по-прежнему остаётся один.
- Шрифты только системные.
- Размеры (базовые, для широкого экрана; на телефоне уменьшай пропорционально): имя в шапке 48–56 px, заголовки разделов 30–34 px, основной текст 17–18 px, межстрочный интервал 1.6.
- Цифры в плитках крупно, 40–48 px; подпись под ними мелко и серым.
- Блоки разделяются воздухом и тонкими линиями. В светлых стилях допускается одна тёмная секция для контраста — только одна. В тёмном стиле чередование тёмных и светлых секций и есть его устройство, ограничение на одну секцию к нему не относится.

**Запрещено безусловно:**

- фиолетовые и сине-фиолетовые градиенты, «космос», свечения, неон;
- матовое стекло, размытые полупрозрачные панели;
- эмодзи вместо иконок;
- стоковые 3D-абстракции, шары, сетки, «нейросетевые» узоры;
- анимации появления при прокрутке, параллакс, счётчики-накрутки цифр;
- слайдеры, всплывающие окна, чат-виджеты, баннеры про куки;
- больше одного акцентного цвета;
- тени поверх теней и скруглённые карточки внутри скруглённых карточек.

Этот список — не пожелание, а граница приёмки. Персональный сайт руководителя такого уровня не должен выглядеть как лендинг стартапа.

### Стили

Четыре готовых стиля внутри этой рамки. Стиль не добавляет и не переставляет блоки: порядок из раздела «Структура страницы» одинаков во всех четырёх. Меняются палитра, шрифтовая пара, кегли внутри допустимых диапазонов, ритм отступов и форма отдельных блоков.

Если стиль заменяет часть блока другой формой — таймлайном вместо прозы, карточками публикаций вместо описаний, — заданная в «Структуре страницы» длина считается по тому, что осталось прозой. Абзацев при этом может быть меньше нижней границы, но не ноль: пока проза в блоке остаётся, её минимум — один абзац, а недосказанное им берёт на себя другая форма. Верхняя граница держится в любом случае.

Шрифтовых наборов два, оба системные:

- гротеск — `system-ui, -apple-system, "Segoe UI", Arial, sans-serif`;
- засечный — `Georgia, "Times New Roman", serif`.

Ничего кроме них не подключай: правило «шрифты только системные» действует во всех стилях. Собрав страницу, посмотри на неё и проверь, что русский текст нарисован выбранным шрифтом, а не подменён системой на другой.

Ещё два правила, общие для всех четырёх:

- панель навигации при прокрутке не меняется — ни цветом, ни подсветкой текущего раздела. Оба эффекта лежат за пределами того, ради чего рамка оставила `script.js`, — плавной прокрутки по якорям и мобильного меню;
- прозрачные варианты тех же трёх цветов четвёртой краской не считаются, но плодить оттенки не надо: двух-трёх уровней прозрачности на весь сайт достаточно.

**1. Светлый лаконичный.** Стиль по умолчанию.

- Палитра: почти белый фон (`#ffffff`), почти чёрный текст (`#111111`), один сдержанный акцент — глубокий синий (`#1f4e79`) либо графитово-зелёный (`#2f4f45`), выбери один.
- Шрифты: гротеск везде, засечных нет.
- Кегли: имя 56, заголовки разделов 30, основной текст 18, цифры в плитках 44.
- Отступы: верх диапазона, 120 px между секциями. Воздуха много, текста мало.
- Усилены: плитки с цифрами — без рамок и подложек, отделены друг от друга только воздухом; результаты — цифра акцентным цветом и крупно, под ней вызов и решение по строке на каждое.
- Подходит, когда важна собранность и короткая подача.

**2. Тёмный премиум с инфографикой.** Единственный стиль с тёмным фоном.

- Палитра: тёмно-синий (`#0f1b2d`), песочно-белый (`#f4f1ea`), золотой акцент (`#c8a45a`). На тёмной секции фон тёмно-синий, текст песочно-белый; на светлой ровно наоборот. Это одна пара в двух инверсиях, новых цветов не появляется.
- Раскладка секций задана жёстко, подбирать её не надо: шапка и плитки с цифрами — тёмные, одним блоком без шва между ними; «Обо мне» — светлая; экспертиза — тёмная; результаты — светлая; контакты — тёмная. Граница между секциями — смена фона, тонкие линии здесь не нужны. Панель навигации тёмно-синяя с песочным текстом на всю прокрутку.
- Золото — цвет крупного и заливок. Мелкий текст золотом на светлой секции не делай, он теряется: набирай его тёмно-синим, тем же цветом, что и остальной текст этой секции.
- Фон — ровная заливка. Никаких градиентов, свечений и переливов: с ними стиль сваливается в запрещённый «космос».
- Шрифты: заголовки и крупные цифры засечные, остальной текст гротеск.
- Кегли: имя 56, заголовки разделов 34, основной текст 17, цифры в плитках 48.
- Отступы: 100–120 px.
- Усилены:
  - плитки с цифрами — на тёмном, цифра золотом, без рамок и подложек;
  - результаты — там, где значение выражается долей или ростом, под цифрой горизонтальная полоса-диаграмма высотой 8–10 px с прямыми концами: дорожка во всю ширину колонки — тёмно-синий с сильно пониженной непрозрачностью, заполненная часть — золото в полную силу, на долю значения. Дорожку приглушённым золотом не делай: на песочном фоне она сливается. Полоса рисуется сразу в конечной длине; расти при прокрутке она не должна, это запрещено рамкой выше. Если полоса выходит не у всех результатов, оставь под неё место и в остальных, иначе соседние карточки разъедутся по высоте;
  - «Обо мне» — один короткий абзац, под ним таймлайн карьеры: 4–6 строк вида «год — роль — организация», слева тонкая вертикальная линия;
  - экспертиза — карточки без фона и рамок, каждую сверху отделяет тонкая золотая линия.
- Подходит, когда за плечами крупные цифры и их надо показать.

**3. Светлый структурный.**

- Палитра: почти белый фон (`#fbfbfb`), почти чёрный текст (`#141414`), один спокойный акцент — синий (`#22548a`).
- Шрифты: гротеск везде.
- Кегли: имя 48, заголовки разделов 30, основной текст 17, цифры в плитках 40.
- Отступы: низ диапазона, 80–90 px: разделов много, страница не должна растягиваться.
- Усилены:
  - панель навигации — якоря на все разделы, включая каждое направление экспертизы по отдельности;
  - экспертиза — 3–4 карточки, в каждой в конце ссылка-действие «Обсудить в Telegram» на тот же адрес, что и кнопка в шапке. Карточки одной высоты, тонкая рамка, без теней.
- Подходит, когда направлений работы много и их надо развести.

**4. Строгий академичный.**

- Палитра: тёплый бумажный фон (`#faf8f4`), почти чёрный текст (`#1a1a1a`), сдержанный акцент — тёмно-бордовый (`#7b2d2d`).
- Шрифты: заголовки засечные, основной текст гротеск.
- Кегли: имя 48, заголовки разделов 30, основной текст 18, цифры в плитках 40. Строгость держится отступами и палитрой, а не размером.
- Отступы: 80–100 px.
- Усилены:
  - «Обо мне» — один короткий абзац, под ним таймлайн профессионального пути строками «год — роль — организация», под таймлайном 3–4 принципа работы, по строке на каждый;
  - результаты — карточками публикаций и выступлений: название, издание и год, одна строка о чём. Публикаций нет, а результаты с цифрами есть — раздел остаётся, но в базовом формате «цифра / вызов / решение»; выбор этого стиля не повод выбрасывать уже собранный материал. Есть и публикации, и результаты с цифрами — не смешивай два формата в одном разделе: спроси, что весит больше, и собери раздел целиком тем, что выберет пользователь. Нет ни публикаций, ни результатов — раздел опускается по общему правилу из «Собери контент», заглушки не ставь.
- Подходит, когда вес держится на биографии, регалиях и публикациях.

**Как выбирать.** Не спрашивай до сборки, какой из четырёх собирать: выбор словами с непрограммистом бесполезен. Собирай первый, он же стиль по умолчанию. Предложение «посмотреть другие варианты» из раздела «Покажи и правь» означает в первую очередь остальные три стиля, а не только смену акцента. Предупреди честно: мгновенного переключения не будет — палитра и кегли живут в `styles.css`, но стили 2–4 меняют ещё и форму отдельных блоков в `index.html`, так что каждый следующий вариант стоит нескольких минут работы. Перед сменой стиля сделай коммит, чтобы было куда вернуться.

### Если есть сайты, которые нравятся

Спроси, есть ли сайты, которые пользователю нравятся внешне. Есть — **проси скриншоты, а не ссылки**.

Ссылка тебе почти ничего не даёт: страницу ты получаешь текстом, а в тексте нет ни цвета, ни шрифта, ни отступов, ни того, как блоки стоят друг относительно друга. Скриншот ты видишь целиком, как картинку. Как снять и передать скриншот — описано в шаге 0.3, объясни тем же способом.

Получив скриншоты, разбери каждый вслух ровно в пять строк:

1. фон и текст — светлые или тёмные;
2. акцентный цвет — какой и где появляется;
3. заголовки — засечные или гротеск;
4. плотность — воздуха много или мало;
5. чем держится страница — цифрами, фотографией, длинным текстом.

Дальше назови, какой из четырёх стилей к этому ближе, и подвинь его в сторону образца: перенеси то, что ложится в рамку, и вслух скажи, что перенести нельзя и почему — например, градиент, вторую акцентную краску или анимацию появления. Целиком макет не копируй: чужая страница собрана под чужое содержание.

## Покажи и правь

**Не устраивай выбор цвета и шрифта до сборки** — обсуждать это словами с непрограммистом бесполезно. Собери один вариант на своё усмотрение внутри рамки, открой в браузере и покажи. Уже на готовой странице предложи посмотреть другие варианты. Это прежде всего остальные три стиля из раздела «Дизайн»: палитра, шрифтовая пара и форма отдельных блоков заданы стилем целиком, поодиночке их не подбирают. Внутри выбранного стиля переключается только акцент, и лишь там, где стиль называет два (в первом — глубокий синий или графитово-зелёный). Мгновенным переключение не будет — что про это сказать пользователю, написано в «Как выбирать».

Дальше цикл: ты меняешь — пользователь смотрит — говорит «ок» — ты делаешь коммит.

## Правила работы

Действуют на обоих этапах.

- Один шаг за раз. Не вываливай простыню из десяти вопросов.
- Не проси выполнять команды за тебя — делай сам.
- Каждое «ок» — коммит с человеческим сообщением.
- «Верни как было» — откат последней правки через git, а без git — из копии папки.
- Если пользователь просит что-то, что нарушает рамки выше, — скажи прямо и предложи решение внутри рамок.
- Если ты чего-то не знаешь или не можешь проверить — скажи это вслух. Пользователь не программист и не отличит уверенное утверждение от догадки, поэтому цена выдуманного ответа здесь выше обычного.
