# Страница профиля и плана

Один самодостаточный HTML в рабочей папке человека: `plan.html`. Собирается сразу после оценки, перерисовывается при каждой следующей.

## Генерация — из шаблона, не с нуля

1. Скопируй `assets/plan-template.html` в рабочую папку как `plan.html`.
2. Замени объект `const DATA = {…}` между маркерами `/* DATA */` и `/* конец DATA */` на данные человека. Больше в файле не меняй ничего.
3. Прогони проверку из раздела «Перед выдачей».
4. Скажи, где лежит файл, и предложи открыть.

Писать страницу с нуля допустимо, только если шаблон недоступен. Ловушки, на которые нарываются при своей вёрстке: подписи осей радара обрезаются, если поле вокруг него меньше 55 пикселей; таблицы внутри колонок сетки распирают их без нулевой минимальной ширины; навигация не должна переполняться на ширине 1060.

## Структура DATA

```javascript
const DATA = {
  meta: { name, role, date, planVersion, labelWas, labelNow, provenance },
  stageWas: { n, score, name, desc },   // предыдущая оценка; равна stageNow на первой
  stageNow: { n, score, name, desc },   // имена стадий — из rubric/stage-map.yaml
  directions: [ { id, title } ],        // 3 направления рубрики
  weakDirection: "<id>",                // минимальный средний уровень
  weakNote: "…",                        // почему это критический путь
  capabilities: [ { id, dir, title, short, level, levelNow, ladder[5] } ],
  moved: [ { cap, from, to, proof } ],  // пусто на первой оценке
  mainStep: { kicker, title, why },
  planStrip: "…",                       // пустая строка, если пояснять нечего
  steps: [ { id, cap, dir, effort, title, why, native? } ],
  inspection: [ { what, found, verdict: "ok|part|no", src } ],
  signals: [ { cap, plumbing, usage } ],
  reassess: [ { id, label, done } ],
  journal: [ { date, version, summary } ]   // новые записи сверху
};
```

Правила заполнения:

- `level` — уровень предыдущей оценки, `levelNow` — текущей. На первой оценке они совпадают: вторая серия на радаре не рисуется, метки «было» не появляются.
- `ladder` — пять формулировок уровней слово в слово из `rubric/aist-pos-rubric.yaml`. Не пересказывать своими словами.
- `short` — короткая подпись оси радара, два-три слова, иначе подписи налезают друг на друга.
- `steps` — только для способностей ниже третьего уровня, в порядке рубрики: сначала самый низкий уровень, при равенстве — из самого слабого направления. Поле `effort` — одно из «15 минут», «вечер», «выходные».
- `inspection` — что реально нашлось при осмотре; в `src` честно разделяй «видно из файлов» и «спросил».
- `provenance` — откуда взяты цифры, если часть уровней восстановлена, а не измерена. Пустая строка, если всё измерено в одном прогоне.

## Перерисовка на следующей оценке

Перенеси прошлые `levelNow` в `level`, проставь новые `levelNow`, заполни `moved` по выросшим способностям с доказательством из системы, добавь запись в `journal`, увеличь `planVersion` на единицу, замени файл.

Отметки, которые человек ставил руками, хранятся в браузере и привязаны к номеру версии плана — поэтому старые отметки не конфликтуют с новой версией.

## Перед выдачей

1. Все секции заполнены, нигде не осталось `undefined`.
2. Ни одного внешнего адреса в файле.
3. Уровни в DATA совпадают с выданными в разговоре — сверь три-четыре выборочно.
4. Эмодзи нет.
5. Если второй серии нет, легенда радара её не обещает.
