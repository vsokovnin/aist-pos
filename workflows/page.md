# Страница профиля и плана

Один самодостаточный HTML в рабочей папке человека: `plan.html`. Собирается сразу после оценки, перерисовывается при каждой следующей.

## Как собирать — три шага

1. Напиши **профиль** в JSON рядом с рабочей папкой: `profile.json`. Образец — `examples/profile.example.json`, форма полей ниже.
2. Запусти сборщик:
   ```
   python3 <папка навыка>/scripts/make-page.py profile.json plan.html
   ```
3. Скажи, где лежит файл, и предложи открыть. Сборщик печатает версию навыка — назови её человеку, чтобы было видно, из какой сборки собрана страница.

**Никогда не собирай страницу поверх существующей `plan.html`.** Она могла остаться от прошлой версии навыка и несёт её структуру: старую разметку, старый набор секций, отсутствие библиотеки. Обновишь в ней данные — человек навсегда останется на прошлогоднем макете. Источник всегда один: `assets/plan-template.html` из папки навыка, а `plan.html` перезаписывается целиком.

**Шаблон не читай и HTML руками не правь.** Вёрстка, стили и проверки уже внутри; всё, что нужно от тебя, — профиль. Скрипт сам подставит данные, проверит целостность и откажется собирать страницу, если в профиле ошибка.

**Страница — файл `plan.html` в рабочей папке человека, а не артефакт чата.** Не строй её серией правок артефакта и не переноси вёрстку в окно разговора: собери файл сборщиком, скажи путь и предложи открыть.

В профиль не пиши то, что одинаково у всех: лестницы уровней, каталог наборов, их описания и значки уже вшиты в шаблон. От тебя только персональное — уровни, шаги, находки осмотра и какие наборы рекомендованы.

## Форма профиля

```
meta        name, role, date, planVersion, labelWas, labelNow, provenance
stageWas    { n, score, name, desc }   — прошлая оценка; на первой равна stageNow
stageNow    { n, score, name, desc }   — имена стадий из rubric/stage-map.yaml
directions  [ { id, title } ]          — направления рубрики
weakNote    почему слабое направление это критический путь
capabilities[ { id, dir, title, short, level, levelNow } ]  — все из рубрики
moved       [ { cap, from, to, proof } ]  — пусто на первой оценке
mainStep    { kicker, title, why }
pinned      [ id набора ] — два-три рекомендованных; остальные видны в библиотеке
nextSteps   [ { id, cap, dir, effort, title, why } ]
inspection  [ { what, found, verdict: "ok|part|no", src } ]
signals     [ { cap, plumbing, usage } ]
reassess    [ { id, label, done } ]
journal     [ { date, version, summary } ]  — новые записи сверху
```

Правила заполнения:

- `level` — уровень прошлой оценки, `levelNow` — текущей. На первой оценке они равны: вторая серия на радаре не рисуется, метки «было» не появляются, плитки не обещают несуществующую историю.
- `short` — подпись оси радара, два-три слова, иначе подписи налезают друг на друга.
- `nextSteps` — **только шаги вперёд**, ровно по одному на способность ниже третьего уровня. Наборы подтягивают шаги сами по полю `cap`, поэтому шаг существует один раз и не дублируется по наборам.
- `pinned` — идентификаторы наборов из каталога: `day`, `meet`, `promises`, `draft`, `followup`, `board`, `report`, `quarter`, `market`, `dossier`, `deck`, `assistant`. Бери два-три, у которых меньше всего незакрытых способностей, и всегда ставь job-наборы выше остальных.
- `effort` — одно из «15 минут», «вечер», «выходные».
- `inspection` — что реально выяснилось; в `src` честно разделяй «осмотр», «ответ», «осмотр и ответ». Не пиши «не найдено» как приговор, если это видно только по текущей папке.
- `provenance` — откуда взяты цифры, если часть уровней восстановлена, а не измерена. Пустая строка — блок не рисуется.

Прогресс набора нигде не хранится: страница считает его сама из уровней способностей. Набор закрыт, когда все его способности на третьем уровне и выше.

## Перерисовка на следующей оценке

Перенеси прошлые `levelNow` в `level`, проставь новые `levelNow`, заполни `moved` по выросшим способностям с доказательством из системы, добавь запись в `journal`, увеличь `planVersion` на единицу и запусти сборщик заново.

Отметки, которые человек ставил руками, хранятся в браузере и привязаны к номеру версии плана — старые отметки не конфликтуют с новой версией.

## Если сборщик недоступен

Только тогда — скопируй `assets/plan-template.html` в `plan.html` и замени блок между маркерами `/* DATA */` и `/* конец DATA */` на `const DATA = <профиль>;`. Больше в файле не меняй ничего. Проверь после: не осталось `undefined`, нет внешних адресов, уровни совпадают с выданными в разговоре.
