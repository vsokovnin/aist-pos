# Страница профиля и плана

Один самодостаточный HTML в рабочей папке человека: `plan.html`. Собирается сразу после оценки, перерисовывается при каждой следующей.

## Как собирать — три шага

1. Напиши **профиль** в JSON рядом с рабочей папкой: `profile.json`. Образец — `examples/profile.example.json`, форма полей ниже.
2. Запусти сборщик:
   ```
   python3 <папка навыка>/scripts/make-page.py profile.json plan.html
   ```
3. Скажи, где лежит файл, и предложи открыть. Сборщик печатает версию навыка — назови её человеку, чтобы было видно, из какой сборки собрана страница.

**Никогда не собирай страницу поверх существующей `plan.html`.** Она могла остаться от прошлой версии навыка и несёт её структуру: старую разметку и старый набор секций. Обновишь в ней данные — человек навсегда останется на прошлогоднем макете. Источник всегда один: `assets/plan-template.html` из папки навыка, а `plan.html` перезаписывается целиком.

**Шаблон не читай и HTML руками не правь.** Вёрстка, стили и проверки уже внутри; всё, что нужно от тебя, — профиль. Скрипт сам подставит данные, проверит целостность и откажется собирать страницу, если в профиле ошибка.

**Страница — файл `plan.html` в рабочей папке человека, а не артефакт чата.** Не строй её серией правок артефакта и не переноси вёрстку в окно разговора: собери файл сборщиком, скажи путь и предложи открыть.

В профиль не пиши то, что одинаково у всех: лестницы уровней вшиты в шаблон, а каталог задач — их обещания, состав и требуемые уровни — лежит в `rubric/job-sets.json` и подставляется сборщиком. От тебя только персональное — уровни, шаги, находки осмотра и какая задача выбрана.

## Задачи и требуемые уровни

Задача (в интерфейсе — «задача», в файле — набор способностей) описана в `rubric/job-sets.json`: группа, значок, обещание и `needs` — по каждой нужной способности требуемый уровень. Требуемый уровень разный у разных задач: «день начинается с одной сводки» требует самостоятельности четвёртого уровня, потому что сводка должна собираться сама; «досье за десять минут» довольствуется третьим.

- **У задачи два круга.** `needs` — что нужно, чтобы она заработала и дала пригодный результат; `hardens` — что добавить, чтобы она перестала подводить. На странице это два подзаголовка: «чтобы заработало» и «чтобы не подводило». Второй круг рисуется всегда, приглушённым, пока первый открыт.
- **Задача готова**, когда по каждой способности из `needs` уровень человека не ниже требуемого. Единого порога «третий уровень» больше нет. Счёт готовых задач и «ближе всего» считаются по первому кругу: человек выбирает, с чего начать, а не где идеально.
- **Опора вне задач.** Верхний уровень `hygiene` в каталоге — способности, которые заводятся один раз и стоят под всеми задачами (сохранность, правило имён, список «где что лежит и что конфиденциально»). На странице это отдельный блок «Файлы и данные: сохранность, поиск, доступ» в секции «Где вы сейчас», не строка внутри задачи.
- **Ступени.** Уровень ниже третьего закрывается одним шагом «завести основу → уровень 3»: даже с первого уровня это один заход, а не два. Дальше ступени берутся по одной: третий → четвёртый, четвёртый → пятый.
- **Горизонты выводятся из ступени, не назначаются на глаз:** заведение основы — «на этой неделе», переход на четвёртый — «в течение месяца», на пятый — «за квартал». Основание — закон убывающей исполняемости: за один заход покупается только основа, выше берётся практикой.
- Каталог задач руками не правь: состав и требуемые уровни — данные, страница читает их сама.

## Форма профиля

```
meta        name, role, date, planVersion, labelWas, labelNow, provenance, mode
stageWas    { n, score, name, desc }   — прошлая оценка; на первой равна stageNow
stageNow    { n, score, name, desc }   — имена стадий из rubric/stage-map.yaml
directions  [ { id, title } ]          — направления рубрики
weakNote    почему слабое направление это критический путь
capabilities[ { id, dir, title, short, level, levelNow } ]  — все из рубрики
moved       [ { cap, from, to, proof } ]  — пусто на первой оценке
chosen      id задачи из каталога — с неё открывается разбор
inspection  [ { what, found, verdict: "ok|part|no", src } ]
signals     [ { cap, plumbing, usage } ]
reassess    [ { id, label, done } ]
journal     [ { date, version, summary } ]  — новые записи сверху
```

Правила заполнения:

- `level` — уровень прошлой оценки, `levelNow` — текущей. На первой оценке они равны: метки «было» не появляются, плитки не обещают несуществующую историю.
- `short` — короткая подпись способности, два-три слова: используется там, где длинное название не помещается.
- **Главный шаг в профиль не пишется.** Страница считает его сама: берёт выбранную задачу, находит первый её разрыв — способность, отстающую от требуемого уровня сильнее прочих, — и показывает рецепт из рубрики. Человек переключил задачу на странице — главный шаг пересчитался под неё. Так шапка и разбор ниже всегда зовут в одну сторону.
- Шаги в профиль не пишутся вообще. Страница берёт их из рубрики: у каждой способности есть рецепт перехода — **что сделать · как сделать · что считать успехом**, — и показывает его под теми ступенями выбранной задачи, которые открыты. Свой текст шага сочинять нельзя ни здесь, ни в разговоре.
- `chosen` — идентификатор задачи из каталога: `day`, `meet`, `promises`, `draft`, `followup`, `board`, `report`, `quarter`, `market`, `dossier`, `deck`, `assistant`. На первой оценке ставь задачу с наименьшим числом ступеней до готовности; если человек назвал свою — ставь её, даже если она дальше. Человек всё равно переключит выбор на странице.
- `inspection` — что реально выяснилось; в `src` честно разделяй «осмотр», «ответ», «осмотр и ответ». Не пиши «не найдено» как приговор, если это видно только по текущей папке. **Строка на каждое направление минимум** — сборщик не соберёт страницу, если строк меньше, чем направлений. Пусто в папке — это тоже пять строк «в этой папке не вижу того-то», а не одна общая на всё: человек должен видеть, что именно смотрели.
- `signals` — по каждой способности, где основа заведена, две вещи: чем видно, что основа есть, и чем будет видно, что человек ей реально пользуется. Основы нет — строки нет: обещать признак того, чего не существует, нельзя. Ни одной строки — секция на странице не рисуется.
- `role` — только со слов человека. Не спрашивал или он не ответил — пустая строка, поле в шапке не появится. Свой вывод о его должности сюда не пиши.
- `provenance` — откуда взяты цифры, если часть уровней восстановлена, а не измерена. Пустая строка — блок не рисуется.
- `mode` — `"full"` для обычной оценки по ответам и `"factual"` для оценки по факту в закрытой области (условия — в `workflows/assess.md`). Поля нет — считается обычной. На странице режим подписан словами, `factual` наружу не показывается.

Готовность задачи нигде не хранится: страница считает её сама из уровней способностей и требуемых уровней задачи.

## Перерисовка на следующей оценке

Перенеси прошлые `levelNow` в `level`, проставь новые `levelNow`, заполни `moved` по выросшим способностям с доказательством из системы, добавь запись в `journal`, увеличь `planVersion` на единицу и запусти сборщик заново.

**Оценка по факту** (`mode: "factual"`) собирается по тем же полям, но сборщик проверяет её строже и откажется собирать страницу, если:

- это первая версия плана — сравнивать не с чем;
- какая-то способность стала ниже, чем была: в закрытой области уровень не понижается;
- выросшая способность не попала в `moved` или попала без доказательства в поле `proof`;
- в `moved` записана способность, которая не выросла;
- стадия оказалась ниже прошлой.

Способности, которых период не касался, оставляй как есть: `levelNow` равен `level`. Это и есть «мы мерили только то, что двигалось».

Отметки, которые человек ставил руками, хранятся в браузере и привязаны к номеру версии плана — старые отметки не конфликтуют с новой версией.

## Если сборщик недоступен

Только тогда — скопируй `assets/plan-template.html` в `plan.html` и замени блок между маркерами `/* DATA */` и `/* конец DATA */` на `const DATA = <профиль>;`. Больше в файле не меняй ничего. Проверь после: не осталось `undefined`, нет внешних адресов, уровни совпадают с выданными в разговоре.
