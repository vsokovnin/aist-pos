# Карта подключений — абстракция в конкретный сервис

Потоки никогда не вызывают сервис по имени напрямую. Они читают `connectors.*` из `aist-pos.config.yaml` и резолвят по таблицам ниже. Это единственное место, где живут имена сервисов, — так навык остаётся портативным между Claude Cowork и Claude Code и не привязан к чьей-то личной инфраструктуре.

**Правило деградации.** Значение `none` или недоступный сервис — поток не падает: работает по тому, что есть, и явно помечает пропущенное. Сервис заявлен, но не авторизован — скажи «нужно подключить X» и продолжай по остальным.

**Правило одного предложения.** Подключение предлагается только когда человек выбрал набор, которому оно нужно, и всегда по одному за раз, с объяснением, какой сценарий оно открывает.

## Почта

| Значение | Сервис | Как подключается |
|---|---|---|
| `yandex` | Яндекс 360 | IMAP и SMTP по OAuth (XOAUTH2), права `mail:imap_full`, `mail:imap_ro`, `mail:smtp`. Для организации — через сервисные приложения в админке |
| `mailru` | Mail.ru и VK WorkSpace | OAuth, IMAP и SMTP |
| `gmail` | Google Workspace | Коннектор Cowork или MCP; личный OAuth на всех планах |
| `outlook` | Microsoft 365 | Только Team или Enterprise с правами администратора, **работает на чтение** |

## Где подключение вообще не нужно

С июля 2026 у Битрикс24 есть **собственный MCP-сервер и MCP Hub**, у Яндекс Трекера — сервер от сообщества. Там, где MCP уже существует, свой коннектор писать не надо: навык пользуется готовым сервером как обычным инструментом. Прежде чем строить интеграцию руками, проверь, нет ли готового MCP.

## Что человек делает сам

Авторизация — интерактивный шаг, за него подключиться нельзя. Навык определяет, что доступно в среде, показывает статус по каждому источнику и ведёт к подключению. Каталог сервисов и рекомендации — `docs/recommended-setup.md`.
